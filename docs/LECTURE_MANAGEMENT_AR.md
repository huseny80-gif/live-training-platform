# إدارة المحاضرات

المسار: `/programs/[id]/lectures`. الوصول من «إدارة المحاضرات» في البرنامج أو صفحة إدارة المحتوى أو المادة الامتحانية. تتطلب جميع العمليات تسجيل الدخول وملكية البرنامج.

- **إضافة محاضرة:** رفع PDF باستخدام مسار الرفع الموجود، ثم استخراج النص ومتابعة الحالة.
- **تعديل الاسم:** يحفظ اسم العرض دون تغيير ملف المصدر أو النص المستخرج.
- **تعديل المحتوى:** ارفع PDF محدّثًا. يُعالج الملف الجديد أولًا؛ بعد نجاح المعالجة تُنقل النسخة السابقة إلى الأرشيف وتصبح الجديدة هي النسخة النشطة. فشل المعالجة لا يحذف النسخة السابقة. الملفات المرفوعة التي لم ينجح اعتمادها تبقى ظاهرة للإدارة وإعادة المحاولة.
- **حذف المحاضرة:** يزيلها من المحتوى النشط ومن خيارات التوليد، ويحفظ الملف والصفحات والمراجع السابقة. تبقى الأسئلة والنتائج والمواد الامتحانية المؤرشفة كما كانت.
- **استعادة المحاضرة:** من تبويب «المحذوفة والنسخ السابقة».
- **عرض النص:** اختر الصفحة من القائمة المنسدلة لعرض نصها الأصلي المستخرج؛ يظهر نص صفحة واحدة في كل مرة. التعديل على المحتوى يكون في PDF ثم رفعه؛ لا يُحرر النص المستخرج يدويًا حتى يبقى توثيق المصادر الحرفي صحيحًا.

لا تعدّل عملية استبدال المحاضرة الأيام والأسئلة القديمة أو تعيد توليدها تلقائيًا. اختر الملف الجديد في المادة الامتحانية لإنشاء محتوى جديد بعد تحديث المحاضرة.

تُرفض إدارة الملف أثناء استخراجه أو أثناء توليد المحتوى المرتبط به، وتُستعاد العمليات المتوقفة باستخدام آليات الاستعادة الموجودة. الأرشفة والاستبدال والتحقق من الحالة والملكية داخل معاملات Serializable. التخزين يبقى خاصًا؛ لا يُنشأ رابط ملف عام.

الترحيل: `20261012100000_lecture_archive` يضيف `archived_at` وفهرسًا دون حذف البيانات. خطوة نشر Vercel الموجودة تطبقه قبل بناء Production. القيم القديمة تكون `NULL` وتبقى جميع المحاضرات الحالية نشطة.

التحقق المحلي:

```sh
npx tsx tests/lectures.test.ts
npx tsx tests/lectures-ui.test.ts
npm run build
```

اختبار الخدمة يستخدم قاعدة بيانات محاكاة؛ اختبار الواجهة يشغّل المكونات الحقيقية ومحاكاة الرفع والمعالجة والـServer Actions في Chromium. لا ترفع الاختبارات ملفات إلى إنتاج ولا تستدعي خدمة AI.
